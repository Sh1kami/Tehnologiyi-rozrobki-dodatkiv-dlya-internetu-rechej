# Розгортання локального стенда

Потрібні Docker Desktop і Compose, вільний порт 8080. У папці fleet скопіюйте .env.example у .env та задайте унікальні JWT_SECRET (щонайменше 32 символи) і FLEET_PASSWORD (щонайменше 12). Порт проксі слухає loopback, брокер лишається у внутрішній мережі Compose.

    docker compose config --quiet
    docker compose up -d --build
    docker compose ps

Інтерфейс відкривається на http://127.0.0.1:8080. Користувачі: dispatch-west, dispatch-east і driver з локальним FLEET_PASSWORD. health повертає 200 коли SQLite та MQTT доступні і 503 коли брокер вимкнений. Для публічного середовища потрібні HTTPS, автентифікація брокера та окремі паролі кожного користувача.

    docker compose exec broker mosquitto_pub -h localhost -t fleet/truck-07/telemetry -m '{"ts":1795129200000,"metric":"speed","value":58}'

Для поточного графіка використовуйте поточний Unix-час у мілісекундах. Код src/smoke.js налаштовується через FLEET_URL і FLEET_PASSWORD. Він перевіряє локальне рукостискання Socket.IO, стан health і метрику диспетчерів без друку токена. nginx.conf передає Upgrade, Connection та використовує proxy_read_timeout 75s. Прямий клієнт wscat не замінює протокол Socket.IO.

Перезапуск backend зберігає SQLite в іменованому томі. Для нормального завершення виконайте `docker compose down`.

## Серверний запуск і відкат

CI збирає образ і на push до main публікує його в GHCR із тегом `sha-…` та `latest`. Для відтворюваного запуску передавайте тег конкретного коміту. На сервері потрібні Docker і Compose v2 з підтримкою `!reset`, клон репозиторію, власний `fleet/.env` і доступ до образу. За потреби увійдіть до реєстру на сервері. Проксі слухає loopback; для публічного доступу потрібні HTTPS і власна конфігурація доступу.

    cd fleet
    bash deploy.sh sha-КОМІТ

Скрипт завантажує образ, чекає healthcheck і перевіряє авторизований Socket.IO та метрику диспетчерів. Після успіху записує тег у `.deployed-image`. Якщо новий запуск або smoke-тест не проходить, скрипт відновлює попередній відомий тег й перевіряє його. Том із даними зберігається.

Для запуску з GitHub Actions налаштуйте середовище `production` із потрібним схваленням. Додайте секрети `FLEET_SSH_HOST`, `FLEET_SSH_USER`, `FLEET_SSH_KEY`, `FLEET_KNOWN_HOSTS` та змінну `FLEET_REMOTE_PATH` з абсолютним шляхом до клону. Запускайте workflow Deploy Fleet Watch вручну, передаючи опублікований тег.

Перед зміною схеми зупиніть запис у SQLite та скопіюйте вміст тому `fleet-data`, включно з базою і супровідними файлами. Перевірте резервну копію розгортанням окремого тестового стека. Відновлюйте у порожній том після зупинки backend.
